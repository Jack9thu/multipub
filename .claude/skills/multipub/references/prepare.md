# 发布前准备：作品做好之后、发布之前

目标是做到「万事俱备，只欠发布」：各平台的标题、简介 / 正文、标签、封面、声明、合集都定好并写进清单，正文渲染查过，
`validate` 和 `--dry-run` 都通过，给用户看确认卡片。**到确认卡片就停**，用户另外明确说「发」之后，才按 SKILL.md 第 5 步发布。

覆盖三种内容：视频（B站 / 抖音 / 小红书视频）、小红书图文笔记、知乎文章。只有一个视频文件、别的什么都没有时，
先读懂视频（有字幕或口播稿就读，没有就转写；抽几帧看画面），再按本文件往下做。

标有「本机适配」的地方，是每个人的环境不同、需要在自己的全局 skill 里补充的内容，见 SKILL.md「本机适配」。

## 依据

- 本文件里的字数、尺寸、数量来自各平台发布页和公开资料（2026-10），平台改版时以发布页为准；字段写法以仓库 `docs/manifest.md`、`docs/platforms/<平台>.md` 为准。
- **本机适配**：有自己的封面 / 标题 / 简介规范文档、题材创作建议时，把路径写进全局 skill，让这一步按它们来。

## 1. 先摸清现有产物

用户给的是**作品目录**时，先读，不要另起一套：说明文件（主旨、来源、状态）、已写好的各平台文案、已有的清单、成片和章节时间轴、
封面和检查图、图卡、文章配图。在现有产物上核对、补齐、修改；改了源文件，就把交付用的副本一起更新。

一份清单只能一种 `kind`，所以一个作品同时有视频、小红书图文、知乎文章时，通常是三份清单（视频一份管 B站 + 抖音，图文一份，文章一份）。

**本机适配**：写明你的作品目录约定（哪个文件是文案、清单放在哪、封面输出到哪），这一步就能直接找到。

## 2. 先定一句话主旨

写任何标题之前，先用一句话说清**作者想回答的问题或想传达的事**（从说明文件、原稿、用户的话里找），拿不准就问用户。
标题、封面大字、简介首句都服务这句话。**不要拿旁支结论当标题**：曾有一个回测作品，作者想分享本地回测、回答「A 股主板最优质、最核心、最低估的资产是哪些」，
却被写成了以统计副产品（「两套门槛都过的只有 7 只」）为卖点的标题和封面，只能全部重做。

然后先写一句不超过 20 字的核心句（主体 + 事件 / 方法 + 结果），再按平台改写，**整句重写，不是只改长度**。
不要标题党、不要和内容无关的热词、不要「最佳」「国家级」等广告法极限词，标题不要和封面大字逐字重复。

## 3. 各平台写什么

| | B站视频 | 抖音视频 | 小红书图文 / 视频 | 知乎文章 |
|---|---|---|---|---|
| 标题 | 15–25 字为宜，可加【系列】或《作品名》，上限 80；给 3 个候选并推荐 1 个 | 12–20 字讲清谁 / 什么事 / 结果，**≤30** | 关键词放前 10 字，**≤20**（emoji 计入） | 15–30 字，上限 100；中文与数字、英文之间加空格；几乎不用感叹号和 emoji |
| 简介 / 正文 | 1–2 句导语 → 概要 → **章节时间戳**（`mm:ss 章节名`）→ 署名区；≤2000 | 一两句说明，首句复述核心关键词；≤1000 | 300–600 字短句短段：痛点 → 方法 → 总结 → 互动提问；≤1000 | 没有简介字段，**首段 100 字内给出结论**；正文是 Markdown |
| 标签 / 话题 | 6–10 个，每个 ≤20 字 | 3–5 个 | 5–8 个，**≤10** | 只用前 3 个，**要有同名话题**（见第 6 步） |
| 封面 | 4:3（如 1440×1080）；16:9「个人空间封面」发完手动换 | 竖 3:4（1080×1440）；横封面发完手动加 | 首图即封面，3:4 1080×1440；所有图统一尺寸 | 横幅约 2.5:1，按 1380×560 做，核心内容在中间约 816px 宽 |
| 写在清单哪里 | 顶层 `title` / `body` / `tags`，`platforms.bilibili.cover`、`tid` | `platforms.douyin.title` / `body` / `tags` / `thumbnail_portrait` | 图文：顶层 `title` / `body_file` / `images` / `tags` | 顶层 `title` / `body_file` / `cover` / `tags` |

- **正文都别写 `#话题`**（话题用 `tags`；纯文本平台里 `#xxx` 只是普通文字），也不要联系方式、二维码、站外链接。
- **署名区**（B站简介末尾，抖音、小红书有地方也带上）：BGM、素材的作者和来源。只写能从作品文件里查到的，查不到就在卡片里留空并问用户，**绝不编造**。
  **本机适配**：写明你的背景音乐、素材放在哪、许可说明在哪。
- **B站分区 tid**：见 `docs/platforms/bilibili.md`，2025 年改版后部分旧 id 可能失效，以创作中心为准。
- **财经、医疗等敏感题材**：不荐股、不承诺收益、加风险提示和数据日期；抖音、小红书对点名个股审核偏严。

## 4. 内容标注 / 声明

**政策**（网信办 2026-05）：发视频必须从 6 类里选一项：含虚构演绎 / 含 AI 生成 / 含营销信息 / 转载 / 个人观点 / 无需标注。
各平台网页端落实得不一样，下表是 2026-10 调研结论（**以发布页当时的样子为准**）。按内容如实判断属于哪一类，在确认卡片里列出，用户确认后才写进清单（铁律 4）。

| 类别 | B站 `platforms.bilibili.creation_statement` | 抖音 `platforms.douyin.declaration` | 小红书 | 知乎 `platforms.zhihu.statement` |
|---|---|---|---|---|
| 无需标注 | `-1`（内容无需标注） | `无需添加自主声明` | 不写（网页端没有这一项，不选也能发） | `none` |
| 含 AI 生成 | `1`（或顶层 `ai_generated: true`） | `内容由AI生成`（或顶层 `ai_generated: true`） | 顶层 `ai_generated: true` → 「笔记含AI合成内容」 | `ai`（包含 AI 辅助创作；或顶层 `ai_generated: true`） |
| 含虚构演绎 | `2` | `虚构演绎，仅供娱乐` | `platforms.xiaohongshu.declaration: 虚构演绎，仅供娱乐` | `fiction`（虚构创作） |
| 含营销信息 | `3` | `内容含营销推广信息` | `platforms.xiaohongshu.declaration: 内容包含营销广告`（选项文字未在真实页面核对过） | 没有对应项 |
| 个人观点 | `4` | `内容为个人观点或见解` | 网页端没有这一项，不写 | 没有对应项 |
| 转载 | `copyright: 2` + `source`（不用 creation_statement） | `内容为转载信息` | `platforms.xiaohongshu.repost_source: 来源名` | 没有对应项 |

- **知乎只能选一个**，除上表外还有 `finance`（包含理财内容）、`medical`（包含医疗建议）、`spoiler`（包含剧透）：财经、投资类文章在 `ai` 和 `finance` 之间问用户选哪个主要。
- **每个平台都显式写上**，包括「无需标注」。multipub 默认什么都不选，但抖音、B站的页面已经把这一项标成必填，不选可能被拦，即使能发出去也不合规。
- 判断依据：封面或画面里有 AI 插画、AI 配音、AI 生成镜头 → 含 AI 生成；剧情、短剧、摆拍演绎 → 虚构演绎；商单、带货、推广 → 营销；
  搬运别人的视频 → 转载；评论、观点类随笔可选个人观点。一个作品同时符合几类时，B站和抖音只能单选，选最主要的一类并在卡片里说明。
- **B站的声明「添加后不可再次编辑」**，确认卡片里要单独列出来；creation_statement 的 id 对应关系未在真实账号逐一验证，发完提醒用户去创作中心看一眼。
- **小红书 `declaration`** 选不上就拒绝发布（笔记没发出，可以安全重试），第一次用某个选项时建议加 `--headed` 看着它选；只靠 `ai_generated` 时选不上只告警、照常发布。
- 抖音的声明选完 multipub 会核实，核实不了就拒绝发布。

## 5. 封面

- **已有现成的**就直接用，但仍要按下面自检。
- **没有就做两张母版**：横版 4:3 1920×1440（字放进中间 1920×1080 安全带，右下角留给 B站时长角标）、竖版 3:4 1080×1440（字避开底部 1/4），
  再导出各平台尺寸。**本机适配**：写明你用什么画封面（AI 画图 skill、代码画图、设计软件）、用什么脚本切尺寸和出检查图。
- **知乎横幅建议单独画**：从横版母版按中间带裁出 1380×560，常常会切掉上下两行字。
- **自检**：用 Read 看各平台尺寸的封面——字没被裁、没被界面挡住、缩到手机屏宽 1/4 还看得清；封面大字和第 2 步的主旨一致；没有二维码、联系方式。
- **发完要手动做的**（在卡片和汇报里提醒）：B站 16:9「个人空间封面」（biliup 只能传 4:3）、抖音横封面（竖横都填时 multipub 只应用竖封面）。
- **视频清单顶层不要写 `cover`**：顶层的值会被每个平台继承，抖音会报 warning，平台块里写 `cover: null` 也盖不掉。每个平台各写各的。
- 抖音页面不设封面会拦「请设置封面后再发布」，有抖音时一定要给 `thumbnail_portrait`。
- 小红书图卡：用 Read 逐张看，数字和正文一致，所有图同一尺寸（否则系统补白边）。

## 6. 正文检查与话题核对

```bash
uv run python .claude/skills/multipub/scripts/content_check.py <清单目录> --topics
```

每份清单都跑一次：知乎文章查 Markdown 渲染，其他平台的正文按纯文本查，`--topics` 核对知乎话题有没有同名的。
规则和修法见 [content-check.md](content-check.md)。有错误就逐处做最小修复，重跑到没有错误；提醒项逐条判断是不是本意。

## 7. 合集

作品属于某个系列时写上（合集要用户先手动建好）：抖音、小红书 `collection: 合集名`，知乎 `column: c_…`，B站发完用 `biliup season add <section_id> --vid <BV>` 补加。
不要擅自新建合集。**本机适配**：把你的合集名、section_id、专栏 id 整理成一张表放进全局 skill。

## 8. 校验、dry-run、确认卡片（到这里停）

```bash
uv run mpub validate <清单目录> --json
uv run mpub publish <清单目录> --dry-run --json
uv run mpub check <平台…> --account <账号> --json      # 登录状态
```

每份清单都要 `validate` 无 error、`dry-run` 通过（顺带看查重：`skipped` + 「同一内容已于…」表示发过）。然后一次性给用户看确认卡片：
每个平台一行——平台 / 账号 / 内容类型 / 推荐标题 / 定时 / 声明 / 合集 / 标签数 / 封面文件，下面附各平台简介全文、标题备选、封面（Read 展示）、
发完要手动做的事、待补项（署名查不到、专有名词待核对、未登录、warning）。

**准备工作到此结束。** 用户要修改就改清单和源文件，重跑第 6、8 步再展示；用户明确说「发」「确认发布」之后，才进入 SKILL.md 第 5 步。
