# 发布前的内容检查（渲染核对）

`mpub validate` / `--dry-run` 只查清单字段（字数、标签数、文件在不在），**不查正文渲染**。
曾经有一篇知乎文章带着 6 处 `**…。**` 原样显示的加粗发了出去，只能删稿重发。所以发文章、图文、视频简介之前，先按本文件检查正文。

## 什么时候查

在 SKILL.md 流程第 4 步 dry-run **之前**，正文改过就重查一次：

| 内容 | 平台怎么显示 | 查什么 |
|---|---|---|
| 知乎文章（`kind: article`，`body_file` 是 Markdown） | multipub 按 Markdown 渲染成知乎 HTML | 渲染结果是否和作者本意一致（下文「Markdown」） |
| 小红书笔记正文、B站简介、抖音描述、知乎想法 | **纯文本**，不渲染 Markdown | 有没有会原样显示的 Markdown 符号（下文「纯文本」） |
| 小红书图卡、封面 | 图片 | 用 Read 逐张看：字没被裁、缩小后看得清、数字和正文一致（脚本管不了） |

## 怎么查

在仓库根目录运行（不在仓库目录时用 `uv run --project <仓库路径> python <脚本路径>`）：

```bash
uv run python .claude/skills/multipub/scripts/content_check.py <post.yaml 或其目录> --topics   # 按清单的 kind 和平台自动选
uv run python .claude/skills/multipub/scripts/content_check.py --md article.md                 # 只按知乎 Markdown 查
uv run python .claude/skills/multipub/scripts/content_check.py --plain 正文.txt --limit 1000
```

- 知乎部分用的是 multipub 发知乎时**同一个解析器**（mistune：CommonMark + 表格、删除线、脚注、公式、自动链接），所以它看到的就是知乎上会出现的样子。
- `--topics`：清单里有知乎时，联网（只读）逐个查话题有没有同名的。没有同名时 multipub 会换成最接近的，可能是书籍（如「量化投资」→「量化投资（书籍）」），换成有同名的词。
- 退出码 0 = 没有错误；1 = 有错误，修完重跑，直到没有错误；提醒项逐条判断是不是本意。

脚本只报告、不修改。**脚本是辅助，不能代替逐处读源码**：它查不出「语法上合法、但不是作者本意」的所有情况（例如本意是两段却写成了一段）。

## Markdown（知乎文章）：逐处检查，最小修复

逐处检查 md 源码，找出按 CommonMark + GFM 渲染后与作者本意不符的写法并做最小修复（**代码块和行内代码里不改**）。常见情形：

| 情形 | 例子 | 渲染结果 | 最小修复 |
|---|---|---|---|
| 中文标点紧贴 `**` 导致加粗失效 | `**结论。**正文` | `**` 原样显示 | 标点挪到外面：`**结论**。正文`；或在 `**` 后加空格 |
| `~` 被配成删除线 | `~~旧~~`、`3~5 和 6~8`（GFM 单个 ~ 也可能） | 删除线 | `\~`，或改写成「至」「到」 |
| `*` 或 `_` 被误识别为斜体 | `2*3*4`、`_x_` | 斜体 | `\*` `\_`，或用反引号包起来 |
| `<xxx>` 被当成 HTML 吞掉 | `<股票代码>`、`<abc>` | 消失 | `\<` 或 `&lt;`，或用反引号包起来 |
| `$` 被当成公式 | `$5$`、`$x$` | 公式 | `\$` |
| 单个换行被合并 | 两行之间没有空行 | 同一段，不换行 | 要分段就空一行；段内换行在行尾加两个空格或 `\` |
| 列表或表格前缺空行 | 段落下一行直接 `| a | b |` | 表格不被识别，变成一段带竖线的文字 | 上方加一个空行 |
| 行首 `#`、`数字.`、`>`、`-` 被误识别 | `2025. 年份`、`> 3%` | 标题、有序列表、引用、列表 | `2025\.`、`\>`、`\#`、`\-` |
| 缩进被当成代码块 | 行首 4 个空格 | 代码块 | 去掉缩进；真要代码块用 ``` 围起来 |
| 表格内 `|` 未转义 | 单元格里写了 `A|B` | 多出一格，整张表可能不被识别 | 写成 `A\|B` |

修的时候：

- **一处一处改，不要整篇批量替换**：用一条正则批量挪标点，曾把三处原本正常的加粗配错了对；改完必须重跑脚本。
- 最小修复：只动出问题的那几个字符，不顺手改写句子。
- 同一篇文章有多份副本（例如带说明的稿子和发布用的正文）时，几份同步改。

已知的正常现象（不是错误）：**知乎表格单元格里的加粗不保留**。线上文章的加粗数会比本地渲染少，少的正好是表格里那几处。

## 纯文本（小红书 / B站 / 抖音 / 知乎想法）

这些平台的正文**不渲染 Markdown**，写了就原样显示：

- 删掉 `**加粗**`、`~~删除线~~`、`` `代码` ``、行首 `# 标题`、`[文字](链接)`、表格。要强调就用「」或 emoji（如 📌）。
- 正文里的 `#话题` 只是普通文字，不会变成话题；话题写在清单的 `tags` 里（写进 YAML 时整个值要加引号，否则会被当成注释）。
- 行首 `- `、`1. ` 会原样显示成短横和数字，可以当作普通分点用。
- 字数上限：小红书 1000、抖音 1000、B站简介 2000（脚本按清单里的平台自动套用）。
- 不放联系方式、二维码、站外链接（平台公约里的违规导流）。

## 线上核对（发完以后）

知乎文章发出后，可以用 multipub 的登录文件调专栏站接口 `GET https://zhuanlan.zhihu.com/api/articles/<文章 id>`（只读），
取 `content` 去掉标签后查有没有残留的 `**`，并核对表格数、图片数和话题。`www.zhihu.com/api/v4/articles/<id>` 要请求签名，会报 403，别用它。
